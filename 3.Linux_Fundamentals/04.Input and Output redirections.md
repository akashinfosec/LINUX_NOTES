# INPUT AND OUTPUT REDIRECTIONS

# 3. Write Text to a File

The `echo` command is used to display text on the terminal. When combined with the output redirection operator (`>`), the displayed text is written to a file instead of being printed on the screen.

## Syntax

```bash
echo "text" > filename
```

## Example

```bash
echo "Hello linux" > output.txt
```

## Explanation

- `echo` prints the specified text.
- `>` redirects the output to the file `output.txt`.
- If the file does not exist, it is created automatically.
- If the file already exists, its previous contents are **overwritten** and replaced with the new text.

### Output

The file `output.txt` will contain:

```text
Hello linux
```

> **Note:** Use `>` when you want to replace the existing contents of a file. To add new content without deleting the existing data, use the append operator `>>`.

---

# 4. Append Text to a File

The append operator (`>>`) adds new content to the end of an existing file without removing its previous contents.

## Syntax

```bash
echo "text" >> filename
```

## Example

```bash
echo "another line" >> output.txt
```

## Explanation

- `echo` prints the specified text.
- `>>` appends the text to the end of the file.
- If the file does not exist, it is created automatically.
- Existing content is preserved.

### Output

The file `output.txt` will contain:

```text
Hello linux
another line
```

### Difference Between `>` and `>>`

| Operator | Purpose | Existing Content |
|----------|---------|------------------|
| `>` | Write/Overwrite | Deleted |
| `>>` | Append | Preserved |

# 5. Count Words in a File

The `wc` (Word Count) command is used to count lines, words, and characters in a file. The `-w` option counts only the number of words.

## Syntax

```bash
wc -w < filename
```

## Example

```bash
wc -w < output.txt
```

## Explanation

- `wc` stands for **Word Count**.
- `-w` counts only the number of words.
- `<` is the input redirection operator, which supplies the contents of the file as input to the command.

### Example File Content

```text
Hello linux
another line
```

### Output

```text
4
```

There are four words:

1. Hello
2. linux
3. another
4. line

> **Note:** If the file contains only:

```text
another line
```

then the command will output:

```text
2
```

because the file contains only two words.

# 6. Redirect Error Output

Linux stores error messages separately from normal output. The `2>` operator redirects error messages (**stderr**) to a file.

## Syntax

```bash
command 2> filename
```

## Example

```bash
ls /wrongdir 2> error.log
```

## Explanation

- `ls /wrongdir` attempts to list a directory that does not exist.
- Since the directory is invalid, an error message is generated.
- `2>` redirects the error message to `error.log`.
- If `error.log` already exists, its contents are overwritten.

### Without Redirection

```text
ls: cannot access '/wrongdir': No such file or directory
```

### With Redirection

Nothing is displayed on the terminal.

Instead, `error.log` contains:

```text
ls: cannot access '/wrongdir': No such file or directory
```

---

# 7. Append Error Output

The `2>>` operator appends error messages to an existing file instead of replacing its contents.

## Syntax

```bash
command 2>> filename
```

## Example

```bash
ls /wrongdir 2>> error.log
```

## Explanation

- Redirects error messages to `error.log`.
- Existing contents are preserved.
- New errors are added to the end of the file.

### Output

```text
ls: cannot access '/wrongdir': No such file or directory
ls: cannot access '/wrongdir': No such file or directory
```

---

# 8. Redirect Both Output and Errors

Sometimes a command generates both normal output and error messages. These can be redirected to the same file.

## Syntax

```bash
command > filename 2>&1
```

## Example

```bash
ls /etc /wrongdir > all.log 2>&1
```

## Explanation

- `>` redirects the normal output (**stdout**) to `all.log`.
- `2>&1` redirects the error output (**stderr**) to the same destination as standard output.
- Both outputs are stored in a single file.

### Output

`all.log` contains:

```text
<contents of /etc>

ls: cannot access '/wrongdir': No such file or directory
```

> **Note:** `2>&1` means **redirect standard error (2) to wherever standard output (1) is currently going.**

# 9. The `tee` Command

The `tee` command reads input from standard input and writes it simultaneously to both the terminal and a file.

## Syntax

```bash
command | tee filename
```

## Example

```bash
echo "linux rocks" | tee output.txt
```

## Explanation

- `echo` prints the text.
- The pipe operator (`|`) sends the output to `tee`.
- `tee` displays the output on the terminal and writes it to `output.txt`.

### Terminal Output

```text
linux rocks
```

### File Content

```text
linux rocks
```

### Append Using `tee`

```bash
echo "another line" | tee -a output.txt
```

The `-a` option appends the output instead of overwriting the file.

### Difference Between `>` and `tee`

| Command | Display on Terminal | Save to File |
|---------|---------------------|--------------|
| `echo "Hello" > file.txt` | ❌ No | ✅ Yes |
| `echo "Hello" \| tee file.txt` | ✅ Yes | ✅ Yes |
| `echo "Hello" \| tee -a file.txt` | ✅ Yes | ✅ Yes (Append) |

---

# Conclusion

Linux provides powerful input/output redirection operators that make working with files efficient.

- `>` writes output to a file by overwriting existing content.
- `>>` appends output to an existing file.
- `2>` redirects error messages.
- `2>>` appends error messages.
- `2>&1` combines normal output and errors into a single file.
- `tee` displays output on the terminal while simultaneously saving it to a file.
- `tee -a` appends output while still displaying it on the screen.

Understanding these operators is essential for logging, debugging, automation, and shell scripting.

# Key Takeaways and the significance of output redirection
Redirecting errors to a file is mainly about:

- Logging for future analysis.
- Debugging applications and scripts.
- Automation, where no human is watching the terminal.
- Keeping output clean by separating successful results from errors.
- Maintaining records of failures for audits and troubleshooting.
